# AISOC Dashboard 0.1 → 1.0 重构交付报告

> 日期：2026-08-05
> 范围：`hermes-agent/aisoc`（前端 + 后端）+ `aisoc/skills/`
> 分支：`aegis-v0.2-ontology-v3`（工作树交付，按里程碑可拆分提交）

---

## 1. 背景与目标

0.1 版存在三类结构性问题：

1. **聊天入口碎片化**：三套异构实现并存——PTY 终端 ChatPage（xterm 嵌 `hermes --tui`，3 条 WebSocket）、右下角 FloatingChat（tui_gateway JSON-RPC）、Ontology Chat（复用 FloatingChat 的 hook + seed system prompt）。会话互不相通，体验割裂。
2. **聊天核心不可控**：`/api/chat/*` 全部依赖仓库级 14k 行的 `tui_gateway/server.py` 与 `--tui` 启动标志，AISOC 无法独立演进聊天协议。
3. **两套视觉体系并存**：主站手写 CSS（`--aisoc-*` tokens）与 Ontology 子模块 Tailwind 4 割裂；QueryClient 为页面级，路由切换即丢缓存。

1.0 目标（已全部达成）：

- 统一会话主模块（所有 Chat 能力收敛到一个模块）
- 特殊能力（Ontology chat 等）通过 **skill 化 + 预定义指令** 接入，不再单独做入口
- 复用 Aegis 的交互模式与 A2UI 轻量方案（自研，不用 Google Agent-to-UI 库）
- 保留右下角悬浮机器人，但降级为便捷入口
- 下线 PTY/TUI 旧链路
- 统一布局与视觉（MASTER.md v3）

范围外（明确不做）：新增菜单模块；事件数据模型重构（Overview 安全事件保持现状，事件本身已是 AI 分析产物）；Ontology scan/roadmap 后端逻辑。

## 2. 关键架构决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 聊天后端来源 | **复制回迁 aegis chat 模块 + 去用户化**（`aegis/backend/chat/` → `aisoc/backend/chat/`），不抽共享包 | aegis chat 本就 import `aisoc.backend.agent_runtime` 的同一 agent 工厂，回迁是依赖方向的自然选择；aegis 一行不改、零回归。1.1 再抽 `chat_core` 共享包 |
| 会话身份 | `user_id=None`（AISOC 单 token 无用户体系） | `_runtime_session_id` 在 user 为空时直接返回原 session id → 聊天会话与 `hermes_state.SessionDB` / `/api/sessions` 天然对齐，Resume/列表零适配 |
| 平台标签 | `platform="aisoc_web"` | SessionDB `source` 字段可区分 Web 聊天 / cron / a2a 会话，前端列表按 `?source=aisoc_web` 过滤 |
| WS 路径 | 新端点 `/api/chat/session` | 过渡期旧 `/api/chat/ws` 被 tui_gateway 占用；选描述性永久路径避免二次改名。M5 移除旧端点后不做 alias |
| 快捷指令存储 | 代码 seed 常量 + `$HERMES_HOME/aisoc_quick_commands.json` 运维扩展文件（mtime 热加载，name 冲突用户文件优先） | AISOC 无自有 DB，不为此引入 SQLite |
| 会话列表 | **后端数据源**（优于 aegis 的 localStorage 方案） | AISOC 已有 `/api/sessions`；跨设备/清缓存不丢会话 |
| instruct_a2ui 文本 | 按 SKILL.md 契约重写并固化为代码 seed | 原文只存 aegis 部署实例的 `aegis.db`，本机（仅 users 表）无存留 |

## 3. 分里程碑交付明细

### M1 — 后端聊天核心回迁

**新增**
- `aisoc/backend/chat/`：`models.py` / `service.py`（ChatSessionManager + ChatSessionActor）/ `routes.py` / `runtime.py` / `attachments.py`，fork 自 aegis 并注明来源
- `aisoc/backend/services/quick_command_service.py`：`@[type_name]` token 服务端展开 + `{var}` 参数替换（语义与 aegis 完全一致，含"不递归展开嵌套 token"的安全约束）
- `aisoc/backend/services/quick_command_seeds.py`：内置指令 seed（见 M3/M4）

**WS 协议**（与 aegis 兼容，fork 关系勿单方面改字段）
- 客户端事件：`session.bind` / `message.send`（含 client_msg_id、attachments、args）/ `approval.respond` / `clarify.respond` / `session.interrupt` / `session.resume`
- 服务端事件 envelope：`message.delta|completed|stream.completed`、`message.accepted`、`run.state`、`tool.started|completed`、`delegate.entered|exited`、`approval.*`、`clarify.*`、`error`；`server_event_id = session:epoch:counter` 供前端去重
- 原生 slash 命令（后端拦截不进 LLM）：`/help` `/model <name>` `/a2a` `/stop`
- **modified_files 通道**：`write_file`/`patch` 成功落盘路径随 `message.completed` 回传（A2UI 自动预览的基础）

**改造**
- `server.py`：挂载 `build_agent_chat_router`（ChatSessionManager/QuickCommandService 单例入 app.state）
- `/api/sessions` 增加 `source` 过滤参数（`session_service.list_sessions` 透传 SessionDB 原生参数）
- `models.py` 补 `ChatQuickCommandResponse` / `ChatQuickCommandListResponse` / `DrawerFileResponse`

**测试**：`tests/aisoc/backend/` 新增 conftest（单 token fixtures）+ 移植 aegis 4 个 chat 测试文件（test_chat_ws 37 例 / attachments / drawer_html / quick_commands，共 51 例，全过）。

### M2 — 前端主会话模块

**新增 `src/chat/`**
- `types.ts`：聊天域类型（Message.sender 改 `'user' | 'assistant'`；Conversation 增 `hydrated`/`remote`）
- `runtime/chatRuntime.tsx`：核心 Provider。与 aegis 的结构性差异——会话列表来自 `GET /api/sessions?source=aisoc_web`，历史会话用 `GET /api/sessions/{id}/detail` 水合后 `session.bind` 续聊；localStorage 只存 UI 偏好（`aisoc_chat_` 前缀）；新增 `openSession(sessionId)` / `interruptActiveConversation` / `refreshSessions`
- `lib/`：`sessionWorkflow.ts`（事件流→执行图投影）、`chatQuickCommands.ts`、`chatDrawerTabs.ts`、`frontendSettings.ts`、`theme.ts`（单主题 aisoc-night + A2UI `{theme_color}` 序列化）、`composerBus.ts`（跨组件 composer 草稿插入总线）——纯 TS 库连测试自 aegis 移植
- `components/`：`ChatLayout`（三栏）、`SessionListPane`、`MessageStream`、`bubbles/`（Assistant/User/ToolGroup/Delegate/ApprovalCard/ClarifyCard/RunStateIndicator）、`Composer/`（contentEditable + `@` 快捷指令 pill + 附件上传 + 打断 + A2UI 开关）、`drawer/`（ChatDrawer 动态 tab、WorkflowPanel、DrawerFilePreview）

**基建**
- `main.tsx`：QueryClientProvider 提升为全局（OntologyPage 删除页面级实例）
- `styles.css`：Tailwind theme/utilities 层全局引入（不含 preflight，手写 CSS 不受影响）；ontology.css 去掉重复引入
- `pages/ChatPage.tsx` 重写为薄组装层，支持 `?session=<id>`（续聊）与 `?quick=<name>`（预填指令 pill）
- `AisocChatProvider` 挂在 AppShell（悬浮球与 /chat 页共享运行时）；Chat 导航项显示注意力徽标

### M3 — A2UI 全链路

- **skill 源**：`aisoc/skills/html-deliverable/`（自 aegis 复制改造）——bridge 引用从 jsDelivr CDN 改为本地 `/agent2ui/agent2ui-bridge.js`（离线可用）；channel `aegis-agent2ui` → `aisoc-agent2ui`；SKILL.md 新增 **Template Extension Points** 章节，登记 `security-incident.html`（事件分析模板）为 1.1 预留契约
- **安装机制**：`services/skill_installer.py` 启动时同步 `aisoc/skills/*` → `$HERMES_HOME/skills/`；`.aisoc-managed` marker 保证只覆盖自管目录，绝不动运维自建 skill
- **静态托管**：`server.py` mount `/agent2ui`（非 `/api` 前缀，鉴权中间件不拦，sandboxed iframe 可匿名加载 bridge）
- **前端闭环**：`message.completed.modified_files` → 自动打开最后一个 `.html` 的 drawer 文件 tab → `GET /api/chat/drawer-html`（工作区根约束，路径穿越 403）→ sandboxed iframe（`sandbox="allow-scripts allow-forms"`, srcDoc）→ bridge postMessage（channel/version/text ≤8000 字校验 + `event.source` 校验）→ composer 草稿插入（**绝不自动发送**）
- **触发**：composer A2UI 开关（localStorage 记忆）→ 消息前注入 `@[instruct_a2ui]`，args 携带 `{theme_color}`（主题 JSON）与 `{date}`
- seed：`instruct_a2ui`（含 `<theme>` 块契约、真实数据要求、"回复不提文件路径"约定）

### M4 — 入口整合

- seed 补全：`instruct_ontology`（原 Ontology Chat 页的 seed system prompt，要求走 `aisoc-ontology` skill、`(node_id)` 引用证据）+ 4 条 `prompt_ontology_*`（原 QUICK_PROMPTS；指令文本内联而非嵌套 token，因 resolve_text 不递归展开）
- `src/chat/FloatingChatWidget.tsx`（88 行）：悬浮球 + 380×560 迷你面板，复用 MessageStream/Composer，与 /chat 页同一活跃会话；`/chat` 路由下不渲染
- 删除旧实现 10 个文件：`FloatingChat.tsx/.css/.test`、`useAgentChat.ts(+test)`（802 行 hook）、`agent-rpc.ts(+test)`、`ChatSidebar.tsx`（死代码）、`OntologyChatPage.tsx`、`useOntologyChat.ts`
- 导航：Ontology 子项删「本体对话」；`/ontology/chat` → `/chat?quick=instruct_ontology` 重定向；StandardGraph / DiffOverview 两页新增「咨询 AI」按钮

### M5 — 旧 PTY/TUI 链路下线

- **后端删除**：`routes/chat.py`（pty/ws/pub/events 四端点）、`services/tui_embed.py`、`main.py` 的 `--tui` 参数与 `HERMES_AISOC_TUI`、`embedded_chat` 全链路（config/server/models/routes/system）、`ontology_service._deprecated_build_chat_answer` 死代码、`tests/aisoc/test_chat_routes.py`
- **前端删除**：旧 PTY ChatPage（含 structure 测试）、`lib/chat.ts`、`@xterm/*` 全部 6 个依赖；SessionsPage Resume 改 `navigate('/chat?session=<id>')`（保留 latest-descendant 追新）
- **影响面**：aisoc 内 `tui_gateway` 仅旧 routes/chat.py 一处 import；顶层 `tui_gateway/` 包与 `hermes --tui` CLI 均不受影响
- 前后端 README 同步改写（启动命令、聊天链路设计、API 清单）

### M6 — UI 统一（MASTER.md v3）

- `styles.css` 新增 `@theme inline` 映射：`--color-aisoc-*` 全套 + `--font-display`/`--font-mono-aisoc`，新代码可直接写 `bg-aisoc-panel text-aisoc-muted font-mono-aisoc`
- AppShell 全量 Tailwind 化（行为全保留）：活动导航 = accent 文字 + `inset 2px` 信号条 + `aria-current`（非颜色标识）；分组 eyebrow = JetBrains Mono 700 大写 0.22em；折叠态/二级菜单/920px 响应式等价重建
- LoginPage/LoginForm/PageMissionHeader/StateBlock Tailwind 化；主按钮实心 cyan + `--aisoc-on-accent` 文字；登录按钮的 cyan 发光按规范移除
- styles.css 删除被迁移组件独占的选择器块（逐一 grep 确认独占）：2649 → 1959 行
- 1.0 导航 IA 定稿：`Overview / Chat / Sessions / Cron / Skills / LLMWiki / Memory / Ontology(Standard Graph, Diff Overview) / Settings`

| 项 | 结果 |

| 前端测试 | vitest **78 通过 + 6 个既有失败**（SettingsPage×5 jsdom localStorage 环境冲突、OverviewPage×1 文案断言；与改动前基线一致，零新增；旧 useAgentChat 相关存量失败随文件删除消失） |
| 冒烟（echo 模式） | WS `session.bind → message.send → delta → completed` 闭环；`@[instruct_ontology]` 服务端展开验证；错误 token 握手拒绝（4401）；SPA/bridge/quick-commands/sessions 过滤/skill 自动安装全通过 |
| 安全 | `drawer-html` 路径穿越返回 403；postMessage 双重校验（source + 协议）；A2UI 只插草稿不发送 |

### 待真实 LLM 手测清单（echo 模式覆盖不到）

1. A2UI 端到端：开 A2UI 开关发「生成一份 XX dashboard」→ agent 走 html-deliverable skill 写 HTML → drawer 自动预览 → 页面点击 KPI/圈选文字 → composer 收到草稿
2. approval / clarify 卡片交互（含刷新后 `session.resume` 恢复 pending 状态）
3. `/model` 热切换、a2a delegate 前台切换、`/stop`
4. `@` 菜单选 `instruct_ontology` → agent 实际调用 aisoc-ontology skill 并给出 (node_id) 引用

  python3 -m aisoc.backend.main --port 9120 --skip-build --no-open

cd aisoc/frontend && npm run dev

## 5. 遗留事项与 1.1 建议

| 事项 | 说明 |
|---|---|
| `chat_core` 共享包 | aegis / aisoc 两份 chat 后端短期并存，bugfix 需人工双写；建议以 aisoc 版为基线抽 `hermes-agent/chat_core/`，aegis 切换后消除漂移 |
| `security-incident.html` 模板 | 契约已登记在 SKILL.md Template Extension Points，1.1 实现（事件头/时间线/IOC 表/影响评估/处置动作，全部元素 agent2ui-object 化） |
| drawer tab 持久化命名空间 | `chatDrawerTabs` 需 userId，现固定 `"aisoc-web"`；多用户共用浏览器会互见 tab 记录（AISOC 单 token 场景下可接受） |
| 显式重连 API | transportError 后靠再次发送/resume 隐式重建 WS；可考虑 runtime 暴露 reconnect |
| 存量测试债 | 前端 6 个既有失败（jsdom localStorage 冲突 + OverviewPage 文案）与后端 a2a SDK 缺失，本次未修；新测试规范：不依赖 jsdom 的 window.localStorage，用显式 storage 参数注入内存 stub |

| 提交拆分 | 工作树含本次全部改动（未提交）；建议按 M1–M6 拆 commit，M5 独立提交便于整体 revert |
